// ====================================
// Design Pattern Notes
// ====================================
// 1. DENORMALIZATION: Guest data is embedded in Reservation document
//    - No JOIN needed to read guest info
//    - Data is synchronized from MySQL during migration
//    - Trade-off: Update guest info requires updating both guest collection and all reservation documents
//
// 2. EMBEDDED ARRAYS: Bill items are embedded in Bill document
//    - All billing information in one document
//    - Atomic reads and writes at document level
//    - Fast dashboard queries without JOINs
//
// 3. DATA SYNCHRONIZATION:
//    - MongoDB serves as cache layer, not authoritative source
//    - MySQL is primary database
//    - Data migrated one-way from MySQL to MongoDB
//    - Migration is idempotent - can be re-run to refresh cache
